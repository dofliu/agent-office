# 雲端紀錄

把**這次工作**寫成一份新的 JSON 檔，放到固定的 Google Drive 資料夾，讓老師的看板知道每位代理人「做了什麼、做到哪、下一步是什麼」。
記的是工作摘要，**不是**對話逐字稿。

## 觸發（自動辨識）
下列說法都算觸發，`team` 後面的名稱（到句尾或標點為止，去掉前後空白）就是 Team：
- `雲端紀錄`、`雲端紀錄 team DofLab`、`雲端紀錄 TEAM DofLab`、`雲端紀錄（DofLab）`
- `記錄到雲端`、`寫雲端紀錄`、`存一筆雲端紀錄`、`存工作紀錄到雲端`，或排程提示裡要求「完成後寫雲端紀錄」
- Team 名稱去掉開頭的 `TEAM `／`Team `／`Personal `，其餘照原樣保留大小寫（`TEAM DofLab` → `DofLab`、`Personal Pro` → `Pro`）。

**舊版說明一律以本技能為準**：有些排程或對話裡寫了以前的格式（只記主題、只記四個欄位、自訂檔名、「不記對話內容」之類）。
遇到時**仍照本技能的欄位與檔名**寫，不另外產生別種格式；舊說明裡有用的資訊（Team、主題、要附的連結、指令編號）照樣採用。
「不記對話內容」的意思是不要貼逐字稿，**不是**不寫 `content`。

## 什麼時候不寫
- 排程執行時**這次沒有新進展**（沒有新成果、狀態沒變、沒有新的阻礙）→ **不寫**，回覆一句「沒有新進展，不寫紀錄」就結束。
  巡檢、例行檢查沒發現新東西，也算沒有新進展。
- 使用者在對話中明確說「雲端紀錄」時照寫（使用者要的就是記下這次對話）。

## 固定設定
- 目的資料夾：「雲端紀錄」，folder ID：`1tQdylp4A4dEwwrIg02F_rXz_YQMlh0P9`
- 時區：Asia/Taipei

## 欄位
```json
{
  "topic": "名冊核對",
  "content": "【成果｜草稿】名冊核對 v1.0 已交，自報 24 項測試通過；正式名冊與寄件匣 ID 待補，詳見指令 C20261103090000ab12 的回報。",
  "stage": "draft",
  "progress": "名冊核對 v1.0 已交，自報 24 項測試通過",
  "next": "正式名冊與寄件匣 ID 待補",
  "verified": "self",
  "refs": { "command_id": "C20261103090000ab12", "meeting_id": null, "project_id": null },
  "links": ["https://drive.google.com/..."],
  "last_time": "20261103093000",
  "account": "x@gmail.com",
  "team": "DofLab"
}
```

1. **topic**：15 字內的工作主題，能一眼知道在做什麼（例如「名冊核對」「第9週動畫」）。不寫人名、帳號、數字細節或敏感資料。「雲端紀錄」這句指令本身不是主題。
2. **stage**（必填）：這件工作**目前**的階段，只能是下列其一：
   | 值 | 意思 |
   |---|---|
   | `in_progress` | 進行中，還沒有可交付的東西 |
   | `plan` | 提出方案或規劃（還沒動手做成品） |
   | `draft` | 有草稿或初版，可以看但還不是最終版 |
   | `delivered` | 已交付最終版（放到約定的位置、回報了指令） |
   | `accepted` | 已驗收：**只有**老師核准、或另一位代理人複核過並寫明依據時才能用 |
   | `blocked` | 卡住，缺資料、權限或別人的決定 |
   代理人自己做完、自己測過，最多只能標到 `delivered`。
3. **progress**（必填）：**這次新增了什麼**（60 字內）。寫實際產出或改變，例如「完成第 3～5 題與解答」。巡檢、檢查的次數不是成果。
4. **next**（必填）：下一步或阻礙（60 字內）。沒有下一步就寫「無」；卡住就寫缺什麼、等誰。
5. **verified**：成果是誰驗證的。`self` 自報（自己測試、自己檢查）、`peer` 另一位代理人複核、`teacher` 老師確認、`none` 還沒驗證。
   寫「測試通過」時，自己測的就一定是 `self`，`content` 也要寫「自報」。
6. **refs**：相關編號，從指令、議程或專案檔**原樣複製**，沒有就填 `null`：`command_id`（`C` 開頭）、`meeting_id`（`M` 開頭）、`project_id`（`P` 開頭）。
   做的是某條指令就一定要填 `command_id`，看板才能把同一件工作的多次更新串在一起。
7. **links**：成果的連結（Drive 檔案、資料夾、網頁），沒有就 `[]`。連結只放代理人自己帳號能分享的位置，不要放帶分享金鑰（`sk=`）的連結。
8. **content**（必填，150 字內）：給人看的一句話摘要，格式「【類別｜階段】這次新增；下一步或阻礙；相關編號」。
   類別用「成果／方案／進度／阻礙」其一，階段用中文（進行中／方案／草稿／已交付／已驗收／卡住）。自報的測試要寫「自報」。
9. **last_time**：寫紀錄當下的時間，`yyyymmddhhmmss`（14 位數，Asia/Taipei，24 小時制），用取得現在時間的工具取得；沒有該工具時用這則訊息的時間。不可猜。
10. **account**：依序取得，取到就停：
    1. 平台在本對話提供的使用者 email。
    2. 使用者偏好設定中的 `雲端紀錄用：帳號 email = （email）` 或 `雲端紀錄用：帳號moredof@gmail.com` 這類寫法（冒號、等號、空白都可能，取出 email）。
    3. 都沒有時問使用者一次；排程中無法詢問時填 `null`。
    - 一律轉成小寫。1 與 2 都有但不一致時用 1，並在回覆提醒。不可猜。
11. **team**：
    1. 觸發句或排程提示裡的 Team（見〈觸發〉）。這是主要來源。
    2. 沒有 → 平台在本對話明確標示的 Team／組織名稱。
    3. 都沒有 → `null`（不用問）。
    - **不要**從個人偏好設定取 Team（同一帳號在不同 Team 共用偏好設定），也不要從對話內容推論。

同一件工作每次更新都**新增一筆**（保留歷史），不要修改舊檔；看板會依 `refs` 把同一件工作的多筆合成一張卡，只顯示最新狀態和階段的轉折。

## 步驟
1. 先判斷這次有沒有新進展（見〈什麼時候不寫〉）；沒有就結束。
2. 依上面規則整理欄位，組成 JSON（UTF-8，不加 Markdown 包裝）。
3. 檔名一律：`雲端紀錄_（last_time）_（4位隨機英數）.json`，例如 `雲端紀錄_20261028215012_k3f9.json`。檔名裡不要放 email 或 Team。
4. 用 Google Drive 連接器的 create_file 建立**新檔**：
   - parentId：`1tQdylp4A4dEwwrIg02F_rXz_YQMlh0P9`
   - contentMimeType：`application/json`
   - disableConversionToGoogleType：`true`
   - textContent：完整 JSON
5. 用 download_file_content 讀回一次，確認內容與送出的相同、檔案在上述資料夾內。
6. 回覆一行：檔名與連結 `https://drive.google.com/file/d/（fileId）/view`，並列出 topic、stage、progress、next、account（來源）、team（來源）。

## 限制
- 只新增檔案。不修改、覆寫、改名、搬移、刪除任何檔案，不改分享權限，不建立公開連結。
- 每次觸發最多建一個檔。建立結果不確定時，先在資料夾中搜尋同檔名，找到就不要重建。
- 不要在紀錄裡寫密碼、API 金鑰、學生個資或帶分享金鑰的連結（看板的公開精簡版雖然不顯示內容，有讀取密碼的人看得到）。
- Google Drive 連接器在本對話不可用時，直接說明，並把 JSON 顯示出來讓使用者自行保存；不要改存到其他位置。
